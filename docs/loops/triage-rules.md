# Issue の仕分け基準

仕分け役（triager サブエージェント、毎朝の Routine）と人が、同じ基準で判定する。

## 判定

| ラベル | 条件 | エージェントがすること |
|---|---|---|
| `agent:ready` | 完了条件が**機械で確かめられる**（テスト・コマンドで合否が出る）／範囲が狭い（目安: 数ファイル）／失敗しても戻せる | 実装して、検証を通した PR を出す（マージは人） |
| `agent:report-only` | 調べれば分かるが、直し方に判断が要る／ドキュメントと実装のずれの洗い出し／依存の更新確認 | 調べて Issue にコメントで報告する。コードは変えない |
| `needs-human` | 要件があいまい（「もっと使いやすく」など）／デザイン・文章のトーンの判断／DB スキーマ・認証・課金・広い範囲／一度きりの判断 | 何もしない。足りない情報を質問としてコメントする |

## リスク

- `risk:high`: DB スキーマ、認証・権限、外部への送信、5ファイルを超えそうな変更
- `risk:low`: ドキュメントだけ、テストを足すだけ、表示の文言だけ
- `agent:auto-merge` は `risk:low` にだけ付けてよい

## 誰がラベルを付けるか

- 仕分け役（エージェント）が付けてよいのは `risk:*` と `needs-human` だけ
- `agent:ready` / `agent:report-only` / `agent:auto-merge` は**人が付ける**（任せるかどうかの判断は人。付けた時点で自動実装のループが動く。ボットが付けたラベルでは動かない）

## 仕分けで書くコメントの形

```
🤖 仕分け: 推奨 agent:ready（risk:low）
理由: 完了条件がテストで確かめられ、範囲が votes サービスだけ
足りない情報: なし
→ 任せてよければ、人が agent:ready を付けてください
```
